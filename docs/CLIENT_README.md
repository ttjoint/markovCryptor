# 客户端交付包 · 使用说明

> 面向使用者。设计与实现见 `CLIENT.md` / `CLIENT_PLAN.md` / `CLIENT_PROGRESS.md`。

## 1. 这是什么

一个挂在 QQ 上的通信客户端。**每台设备一个 QQ 号**，界面上是好友列表，
每个好友一条独立信道。

它做两件普通聊天软件不做的事：

1. **图片密文**：把文字藏进一张真实照片里发出去，QQ 上看起来只是发了张图
2. **文本密文**：把文字藏进一段生成的中文里，看起来只是发了句话

收到藏了东西的消息时，明文窗显示对方正常看到的内容，**密文窗**显示解出来的
隐藏内容。

## 2. 包里有什么

```
qqclient-<版本>/
  start.bat        ← 双击这个
  start.ps1        实际逻辑（start.bat 调用它）
  python/          自带 Python 3.12 + 全部依赖（不用装任何东西）
  node/            SnowLuma 的运行时
  snowluma/        OneBot 桥（负责和 QQ 通信）
  models/          4 个中文文本模型（文本密文用）
  manifest.json    包信息
```

**目标机器不需要装 Python，不需要装 Node。** 只要 Windows 10 或更高。

## 3. 怎么用

### 3.1 第一次

1. 把整个 `qqclient-*` 文件夹解压到任意位置（路径别太深）
2. **先打开 QQ 并登录**——这一步无法自动化。SnowLuma 只能挂到**已登录**的
   QQ 进程上，它不能替你输密码
3. 双击 `start.bat`

它会依次：找到本机已登录的 QQ → 起 SnowLuma → 起界面 → 用你的默认浏览器
开一个无地址栏的独立窗口。

**不需要输入 QQ 号。** SnowLuma 会写出 `snowluma/config/onebot_<你的QQ号>.json`，
文件名就是账号，程序从中读出来。

第一次会看到三步引导清单：图片文件夹、文本模型、去好友列表点人。

### 3.2 必做：设置图片文件夹

**没有图片文件夹就无法发起握手，也就没有密文信道。**

点左上角齿轮 → 「添加文件夹…」→ 选一个**你自己照片的文件夹**。

- 程序只记录路径，**不复制、不删除**你的图片
- 每次发送从里面随机（或按文件名）取一张
- 太小的图（装不下握手报文）会被自动跳过
- 待发队列上限默认 8 张，可改

> **为什么必须是真实照片**：QQ 对程序生成的噪声图有风控。用你相册里本来就有的
> 照片，看起来才是正常人在发图。

### 3.3 建立信道

1. 左侧「好友」→ 点一个好友
2. 点「发起密钥交换」——会消耗一张图片，把它发过去
3. 等对方也装了本系统并回复，状态变成「信道已建立」

对方第一次给你发握手图时，如果你队列里有图，会**自动回复**，不用手动操作。

### 3.4 发送

- **发送**：普通消息，对方在 QQ 里直接看到
- **密文发送**：需要先建立信道。优先走文本信道（不消耗图片），
  文本模型不可用时走图片

### 3.5 文本模型

包里自带 4 个。齿轮 →「文本模型」页可以：

- **训练**：选一个 UTF-8 中文语料文件（小说、文集都行），起名，训练
- **导入**：把别处拿到的 `.json` 模型复制进来
- **导出**：复制出去给别人
- **删除**：只删模型目录里的文件

**不需要和对方约定用哪个模型。** 解码端会把手里所有模型逐个试，认得出是谁写的
就解出来；认不出就当普通文本，静默丢弃。

## 4. 重要：数据不留存

**本程序不落盘任何聊天数据。** 退出即销毁：

- 好友列表 —— 每次启动从 QQ 重新读
- 聊天记录 —— 每次点开好友从 QQ 重新读
- **待发图片队列** —— 关掉程序就清空
- 会话密钥 —— 只在内存

只有配置（图片文件夹路径、队列上限、模型目录）会写到
`%APPDATA%\markovcryptor\client.json`。那里面没有聊天内容。

## 5. 出问题了

### 双击后什么都没发生

看日志：`%APPDATA%\markovcryptor\client.log`

`start.bat` 在失败时也会打印日志末尾 12 行。

### 一直提示「正在等待 QQ 登录」

**QQ 没登录。** 先打开 QQ 输密码/扫码，再双击 start.bat。

### 提示「OneBot 端口没起来」

看 `snowluma/logs/` 下的日志。也可能是端口被别的程序占了。

### 界面空白 / 打不开

1. 确认 `python/Lib/site-packages/markovcryptor/client/webui/index.html` 存在
2. 手动访问 `http://127.0.0.1:8741/` 看报什么错

### 握手一直「等待对端回复」

对方必须也装了本系统并点了「发起密钥交换」或收到后自动回复。
**双方都要配好图片文件夹**，否则回不了。

### 「没有可用的图片」

图片队列空了，或配置的文件夹里没有可用的图。
齿轮 → 检查文件夹列表，标黄的是「配了但里面没有可用图片」。

## 6. 已知限制

- **只支持 Windows**。SnowLuma 是注入 Windows 版 QQ 进程的，
  手机 QQ 是完全不同的协议栈，没有等价的可注入点
- **每台设备一个 QQ 号**。同机挂多个号时会在启动时让你选，但推荐一对一
- 界面用 2.5 秒轮询刷新，新消息最多延迟 2.5 秒出现
- 好友列表行暂时不能用键盘 Tab 选中（鼠标可用）
- **文本解不出来时程序不回复任何东西**。这是刻意的：任何自动回包都可能在
  信道上留下程序化痕迹。宁可对面收不到回应

## 7. 端口

| 用途 | 端口 |
| --- | --- |
| 客户端界面 | 8741 |
| SnowLuma WebUI | 5099 |
| OneBot WS | 由 SnowLuma 分配（常见 3000/3001） |

全部只监听 `127.0.0.1`，不对外网开放。
