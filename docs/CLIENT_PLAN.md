## 阶段 1：传输层地基

**为什么先做这个**：一对多必然要求「按发送者路由」。现在的 `_sinks` 是
无差别广播，一接多好友立刻串台。这个不改，上面盖什么都会塌。

### 1.1 sink 按发送者路由

- `onebot.py` 的 `register(address, sink)` 改为 sink 能声明「我只关心谁的消息」。
- 最简形式：`register(local_address, sink, accept=lambda peer: ...)`，
  或者让 sink 带 `peer` 属性，`_handle_event` 按 `sender` 精确投递。
- 现有测试端只有 alice 一个终端，用它保证不回归。

**验收**：新增测试——A 发给 B 的包，不得进入 C 的终端。

### 1.2 请求-响应

- 新增 `ask(action, params, timeout)`：发出去，用 `echo` 匹配回来，
  不像 `send` 那样发完就不管。
- 当前 `_outbox` 只有发；需要读取循环里区分「这是响应」还是「这是事件」。
- 已实测可用的动作：`get_friend_list`（29 个好友，字段
  `user_id/nickname/remark`）、`get_friend_msg_history`、`get_stranger_info`、
  `get_login_info`。

**验收**：能从真实 SnowLuma 拉到好友列表并打印前几条。

### 1.3 原始事件回调

- 新增 `on_event(callback)`：把**普通 QQ 消息**（没有隐写的那种）也抛给上层。
- 现在隐写层对无密文消息静默丢弃，界面上就看不到「对方发送了图片」。
- 事件里要带足够的原始段信息，供上层做「无法解析就显示一行字」。

**验收**：收到一条普通图片消息时，上层回调能拿到它。

### 1.4 回归

- 跑全量测试，测试端的 alice/bob 双窗必须一切照旧。

## 阶段 2：多会话管理

### 2.1 好友目录

- `markovcryptor/client/directory.py`
- 拉 `get_friend_list`，内存里存 `{uin: {nickname, remark}}`。
- **不落盘**（见 CLIENT.md §5）。
- 显示名规则：有备注用备注，否则昵称。

### 2.2 会话容器

- `markovcryptor/client/conversations.py`
- `{peer_uin: Conversation}`，每个 Conversation 内含：
  - 独立 `Terminal`（密钥交换状态独立）
  - 未读计数
  - 最后一条消息时间
  - 独立图片队列引用
- **懒创建**：29 个好友不预建 29 个 Terminal。点开或收到消息时才建。

### 2.3 一对多验证

**验收**：用脚本对两个好友各发一条握手，各自独立进入「等待对端回复」，
互不影响。这是本阶段最关键的验收点。

## 阶段 3：图片队列

### 3.1 配置

配置文件只存**路径和选项**，不存图片本身：

```json
{
  "queue": {
    "folders": ["D:/Pictures/covers"],
    "max_items": 8,
    "pick": "random"
  }
}
```

`pick` 取值 `random` 或 `sequential`（按文件名）。

### 3.2 取样与预筛

- 进队时从文件夹挑一张**还没入过队**的。
- **预筛**：立刻判断这张图装不装得下握手报文，装不下直接跳过并记日志。
  不能等发的时候才发现——用户已经白排了。
- 队列上限默认 8（5~10 可配）。
- 文件夹有几千张表情包时不能一次全读：先只取文件名列表，按需读内容。

### 3.3 绝不删除用户文件

- 出队只是从队列移除，**不动文件夹里的图**。
- 下次启动可能又挑到同一张——这是可接受的，写进配置注释。
- 队列本身**不落盘**，退出即清空，UI 上要明写。

**验收**：纯逻辑单测——取样不重复、装不下的被跳过、队列不超上限、
文件夹内容未被修改（对比操作前后的文件列表与哈希）。

## 阶段 4：新前端

- `markovcryptor/client/webui/index.html`（单文件、零依赖，与现有一致）
- 左侧好友列表：未读红点、信道状态标记
- 右侧：明文窗 + 密文窗 + 图片队列（沿用 alice 形态）
- 点开好友**才**拉历史（`get_friend_msg_history`）
- 消息渲染：
  - 图片、文本 → 正常显示
  - 其余（语音、抖动、转发、XML/JSON 卡片…）→ 一行小字「对方发送了 XX」
- 多 QQ 号时启动先出选择列表

> 动手前参考 GitHub 上接 OneBot 的美化版 QQ 客户端，抄它们的消息分类。

**验收**：Playwright 截图，确认好友列表、红点、两窗、一行小字的降级显示。

## 阶段 5：启动器（零安装）

### 5.1 打包

- Python embeddable（`Lib` 去 site-packages 仅 21.8MB）
- 依赖 wheels 离线安装
- Node + SnowLuma 随包

### 5.2 launcher.exe

- .NET Framework 4.8（Win10 1809+ 内置，实测自带 `csc.exe`）
- 流程见 `CLIENT.md` §10

### 5.3 必须避开

- **不能用裸 `python`**：`WindowsApps\python.exe` 是微软商店 stub，实测指向
  `AppInstallerPythonRedirector.exe`。一律用包内绝对路径。

**验收**：干净 Win10 虚拟机（无 Python、无 Node），双击到能聊天。
